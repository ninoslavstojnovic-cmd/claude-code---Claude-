# PRD：待办清单网页

> PRD = Product Requirements Document（产品需求文档）。
> 它回答的是“要做什么、为什么做、做到什么程度算完”，**不回答“代码怎么写”**。
> 下面每一节开头的引用块是给自己的学习注释，真实 PRD 里可以删掉。

## 1. 背景：为什么要做

> 先讲问题，不讲方案。没人觉得这是问题，就不值得做。

平时工作和生活里的琐事很多，经常忘。手机备忘录太杂，专业待办软件要注册、功能太多。
想要一个**打开浏览器就能用**的小清单。

## 2. 目标用户

> 写一个具体的人，不写“所有人”。

我自己：电脑前时间多，想随手记下待办，做完打个勾。

## 3. 目标：做成了是什么样

> 可以检验的结果，而不是“好用”“漂亮”这种形容词。

- 30 秒内能记下一件事
- 关掉浏览器再打开，清单还在

## 4. 功能需求

> 分优先级。P0 = 第一版必须有，P1 = 以后再说。

| 编号 | 功能 | 优先级 |
|---|---|---|
| F1 | 输入框 + “添加”按钮，按回车也能添加；空内容不能添加 | P0 |
| F2 | 点击任务切换“已完成”，已完成显示删除线 | P0 |
| F3 | 每条任务有删除按钮 | P0 |
| F4 | 数据存在浏览器本地（localStorage），刷新不丢 | P0 |
| F5 | 按“全部 / 未完成 / 已完成”筛选 | P1 |
| F6 | 给任务设截止日期 | P1 |

## 5. 不做什么（范围之外）

> 这一节最容易被忽略，但最能防止项目越做越大。

- 不做登录注册、不做多人共享
- 不做服务器和数据库，只在本机浏览器保存
- 第一版不专门适配手机

## 6. 验收标准：怎么算做完

> 每条都能让别人照着点一遍，回答“是 / 否”。

- [ ] 输入“买牛奶”按回车，列表出现“买牛奶”
- [ ] 输入框为空时点添加，列表不变
- [ ] 点击“买牛奶”，出现删除线；再点一次，删除线消失
- [ ] 点删除按钮，该任务从列表消失
- [ ] 添加 3 条任务后刷新页面，3 条都还在

## 7. 技术约束

> 只写“必须遵守的限制”，具体怎么实现留给开发（或 Claude）决定。

- 一个 `index.html` 文件就能跑，双击即可在浏览器打开
- 不用任何框架和第三方库

在项目目录里对 Claude 说：

```
按照 docs/PRD.md 实现第一版（只做 P0），做完后逐条对照第 6 节验收标准自查。
```
